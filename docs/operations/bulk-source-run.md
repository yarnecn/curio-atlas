# 页面与网站抓取

Python 已内置在生产镜像中，不需要单独安装。所有抓取结果先成为证据或待审候选，不会自动发布。

## 手动抓取

1. 登录 `/admin/operations`。
2. 新增来源：抓一个页面就选“只抓这个页面”；抓入口下的一组页面就选“从这个入口发现同站页面”，并设置最多 2—20 页。
3. 不需要定时运行时，不勾选“按检查间隔自动维护”。
4. 保存后点击“立即抓取”。worker 会马上调用 Python；全局自动维护即使关闭也不影响手动抓取。
5. 在下方查看证据，到 `/admin/review` 审核 AI 候选。

## 从指定网站自动抓

1. 分别新增你允许自动维护的来源，URL 填允许开始发现内容的 HTTPS 目录入口，例如 `https://example.org/science/`。
2. 选择“从这个入口发现同站页面”，设置每次最多 2—20 页，并勾选“按检查间隔自动维护”。
3. 在 `app.config.json` 将 `sources.automationEnabled` 设置为 `true`，重启容器。

Python 只跟随：

- 与入口完全相同的域名、协议和端口；
- 与入口相同路径范围内的 HTML 页面；
- `robots.txt` 允许访问的页面；
- 单轮不超过该来源设置的页数，最多 20 页。

“抓取范围”和“运行方式”互不绑定：单页或站点都可以手动点一次，也都可以开启定时维护。

它不会跨站，不抓图片、PDF、压缩包和脚本，不保存网页全文。单页响应大小、超时、批次和调度周期统一由 `app.config.json` 的 `sources` 控制。

## AI 模式

- `rules`：免费，只保存证据，不生成候选。
- `ollama`：本地模型根据证据生成待审候选，不按 Token 付费；模型服务地址仍在管理台选择。
- `openai_compatible`：使用配置文件中的 `ai.apiKey`，费用由供应商决定。

无论哪种模式，内容指纹未变化时不会重复生成证据或消耗 AI Token。

## 批量导入

管理台单次最多导入 200 个来源。模板见 `content/source-feeds.template.txt`：

```text
话题slug | 来源名 | 发布机构 | HTTPS入口 | 来源类型 | 许可 | 间隔小时 | single_page/website | 最多页面 | true/false自动维护
```

指定网站不等于默认拥有转载许可。系统只保存核验所需的短摘录、地址、时间和内容指纹；站长仍需确认来源许可与最终事实。
