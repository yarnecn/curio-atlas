# Phase 1 实现说明

## 2026-09-07 当前数据库与启动基线

- 数据库已改为 MySQL 8.4，运行时只使用 `mysql2` 和 MySQL SQL；
- 不转换旧数据库数据，不维护双数据库兼容层，不提供迁移、回滚、单独 seed 或站长初始化命令；
- `npm start` 会构建应用，幂等检查空库结构、首版目录、20 篇 starter 常识和站长账号，再启动 Web、API 与 worker；
- `npm run image:build` 构建包含 Web、API、worker 和 Python 抓取器的 `curio-atlas:0.1.0`；
- 所有用户运行参数只读取 `config/app.config.json`。
- CI 的 MySQL 烟测会自动执行注册、投稿、自投票无效、规则 AI、内部候选、人工发布、合并和版本回滚，并在结束后删除测试数据。

## 2026-09-04 增量验收状态

- 浏览无需账号；注册只要求昵称账号和密码，不收集真实姓名、手机号或邮箱；
- 写接口统一从服务端会话读取身份，旧 `x-user-id` 直通已删除；普通账号不能进入审核和运营后台；
- 密码使用 Node.js `scrypt` 派生后保存，会话仅保存随机 Token 的 SHA-256 摘要，并设置 HttpOnly、SameSite Cookie；
- 首页从 3 条扩展为最多 12 条，按一级领域已发布库存比例分配后交错展示；
- 正式常识新增详情页及“顺着看”，现有发布内容已回填同领域关系，新发布内容会自动建立同话题和同领域关系；
- 运营台可批量导入最多 200 个白名单入口；既可立即抓一个具体页面，也可从指定站点入口发现最多 20 个同源同路径页面，并按来源开关自动维护。
- 生产交付已收敛为一个含 Web、API、worker 和 Python 的版本镜像，外部只需挂载一个 JSON 配置文件并提供 MySQL、Redis。

当前账号模块是可运行的最小安全基线，不等于公开生产认证已全部完成。找回密码、封禁与注销、管理员多因素认证、请求限流及最终投稿合规方案仍是上线门槛。

## 当前账号与权限

当前提供昵称账号注册、登录、退出和会话查询。浏览公开内容不检查会话；投稿和评分要求任意登录账号；审核、发布、版本、分类、AI 与来源管理只允许 `reviewer` / `owner`。

应用按 `app.config.json` 的 `owner.handle` 创建或初始化站长，不含默认密码；已有站长密码默认不会被重置。公开注册始终创建普通 `user`，不能提升自身角色。

连续 15 分钟内 5 次密码失败会锁定账号 15 分钟。更新站长密码会使其旧会话全部失效。

## 启动数据服务

MySQL 和 Redis 就绪并完成 `config/app.config.json` 后，只运行：

```bash
npm start
```

项目不负责下载或创建 MySQL、Redis；浏览器和小程序不能直接连接 Redis，只有 API 与 worker 使用它。

## 已提供的接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/topics` | 获取可投稿话题 |
| GET | `/auth/me` | 查询当前会话 |
| POST | `/auth/register` | 注册昵称账号并建立会话 |
| POST | `/auth/login` | 登录并建立会话 |
| POST | `/auth/logout` | 删除当前会话 |
| GET | `/submissions` | 获取公开尝试池 |
| POST | `/submissions` | 认证投稿者提交候选 |
| PUT | `/submissions/:id/vote` | 登录用户更新有用 / 没用评分 |
| POST | `/admin/editorial-candidates` | 审核者创建来源发现、覆盖缺口、维护或站长种子候选 |
| GET | `/admin/review/submissions` | 审核者读取审核队列 |
| POST | `/admin/review/submissions/:id/decision` | 创建、合并、暂缓或驳回 |
| GET | `/knowledge` | 获取已发布正式常识 |
| GET | `/knowledge/slug/:slug` | 获取正式常识详情和相关常识 |
| GET | `/knowledge/:id/revisions` | 审核者读取正式常识版本历史 |
| POST | `/knowledge/:id/rollback` | 审核者复制目标旧版并生成新的已发布版本 |

写接口使用 HttpOnly 会话 Cookie。所有身份、角色、校验、状态迁移和晋级判定均在服务端执行；客户端传入用户 ID 不会获得权限。

扩大尝试和进入审核队列的门槛保存在 MySQL 的 `policy_config`。评分聚合会在同一事务内读取当前策略；配置缺失或数值非法时回退到已审核的安全默认值。

## AI 运行模式

投稿会在 MySQL 建立 `ai_jobs` 记录，并向本机 Redis 的 `content-ai` 队列提交任务。worker 并发固定为 1。站长可在 `/admin/operations` 选择：

- `rules`：默认零 Token 规则模式；
- `ollama`：调用本地 Ollama，消耗本机算力但不按 Token 付费；
- `openai_compatible`：连接 OpenAI 兼容 HTTPS 接口，生产密钥只读取挂载配置的 `ai.apiKey`。

规则模式完成：

- 压缩多余空白并统一结尾标点；
- 检查缺少来源、提问式内容和少量高风险绝对化用语；
- 保存原稿、处理稿、风险标记、模型名和 Prompt 版本；
- 用户投稿无风险时进入小流量尝试，内部候选无风险时直接进入人工审核；有风险时统一进入暂缓状态。

`ai_jobs` 同时充当持久任务记录。即使 MySQL 已提交后 Redis 短暂不可用，worker 也会按固定间隔重新发现并入队仍处于 `queued` 的任务，避免候选永久卡在预处理状态。

本地或远程模型接收的是经过程序裁剪的结构化证据包，不接收整页网页。每次调用记录供应商、模型、输入/输出 Token 和 Prompt 版本；不知道供应商单价时费用保留为空，不伪报为零。

## 白名单来源闭环

来源管理、Python 抓取器和定时 worker 已接通：

1. 站长把具体 HTTPS 页面或有页数上限的同站目录绑定到细分话题；
2. worker 只领取到期且启用的来源；
3. Python 限制响应大小，阻止私网地址，只提取相关短段落；
4. MySQL 保存页面哈希、必要证据和检查状态，不复制第三方全文；
5. 页面未变化时不调用 AI；
6. 有变化且启用本地/远程模型时，生成内部候选并直接进入人工审核；
7. 规则模式只积累证据包，避免用伪 AI 自动编写事实。

手动“立即抓取”始终可用；持续维护需要来源自身勾选自动维护，并在 `app.config.json` 设置 `sources.automationEnabled=true`。失败任务会保存错误并延迟重试，不影响公开阅读。详细操作见 `docs/operations/bulk-source-run.md`。

## 正式版本回滚

正式常识的已发布版本不允许原地覆盖。合并候选会追加新版本；回滚会复制目标版本的结构化内容和来源 claim，再生成版本号更高的新版本，同时记录审核理由、审批记录和审计日志。管理入口为网站 `/admin/knowledge`。

## 样例数据

空库初始化包括：

- 12 个知识领域和 48 个细分话题；
- 20 个带来源、正式版本、claim 和短文 sections 的 starter 常识；
- 3 个来源记录、内容关系和审核阈值；
- 配置指定的站长账号。

种子内容用于验证模型和流程，并已满足页面的闭环展示格式；公开上线前仍要逐条核对来源是否真正支持结论，再将它们视为正式编辑成果。
