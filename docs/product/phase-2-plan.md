# Phase 2 Web 产品计划

- 状态：进行中
- 启动条件：生产环境已部署，产品负责人确认先完善 Web，暂不让小程序阻塞 Web 迭代。
- 原则：Web 和小程序共用内容、API、账号和审核规则，但不复用同一套页面结构、信息密度或交互流程。

## Phase 2 目标

把已经跑通的内容内核，变成真正“打开就能看、看完还想继续看”的 Web 常识百科，并让没有用户投稿时也能持续产生可审核内容。

## Web 范围

1. 首页浏览流：跨领域铺开内容，保留领域轮换、质量和新鲜度，逐步加入已读去重。
2. 阅读体验：短而闭环的正文、预计阅读时长、常见误解、边界、来源和复核时间统一呈现。
3. 继续阅读：相关常识按组成、对比、因果、前置知识和现实例子组织，形成可连续浏览的路径。
4. 反馈与收藏：有用 / 没用、收藏和跳过作为推荐信号，不增加公开评论区。
5. 内容供给：白名单来源、覆盖缺口、维护任务和 AI 候选在后台可观察、可批量审核，不自动发布事实。
6. Web 生产质量：错误、空状态、弱网、缓存、移动端布局、权限和安全提示统一收口。

## 执行顺序

Phase 2 按下面的顺序推进，不并行堆叠互相依赖的功能：

### P2-0 内容质量封装（当前最高优先级）

- 先逐条复核 20 篇 starter，修正“只说了一半”的表述、来源和边界；
- 按 12 个领域分批生产和审核其余 145 个 V1 题目；
- 固定每篇内容的最小结构：直接结论、解释、例子或误区、边界、来源和复核时间；
- 不用批量抓取结果直接替代正式编辑，抓取内容只能进入候选或证据包。

完成条件：首版公开内容数量和质量可被站长逐条确认，首页不再靠少量样例支撑体验。

### P2-1 浏览闭环（已开始）

- 已实现未读优先、浏览器本地已读、清除已读、跨领域比例和标题关键词搜索；
- 下一步补充首页卡片的信息层级、继续阅读入口和移动端阅读节奏；
- 关系推荐优先使用前置知识、对比、组成、因果等自然关系，不追求复杂算法。

完成条件：未注册访客连续阅读 3 条仍能理解内容，并能自然进入下一条相关常识。

### P2-2 轻量反馈闭环

- 先增加正式常识的有用 / 没用反馈和本地收藏，不要求登录才能阅读；
- 有真实使用数据后，再决定哪些反馈需要绑定昵称账号并同步到云端；
- 反馈只用于排序、重写和复核优先级，不作为事实真伪证明。

完成条件：站长能看到内容价值信号，但不会因为单条低票就永久隐藏探索内容。

### P2-3 最小内部供给循环

- 把来源检查、页面变化、证据包、AI 候选和人工审核状态在运营台串成一条可追踪记录；
- 优先显示待处理积压、来源失效、复核到期和领域覆盖薄弱项；
- 规则模式保持零 Token；需要生成或改写时再选择 Ollama 或 OpenAI 兼容接口。

完成条件：没有用户投稿时，站长仍能从运营台看到下一批可审核工作，而不是手工翻日志。

### P2-4 生产质量收口

- 增加 API 失败、空数据、慢请求和队列积压的可理解提示；
- 对公开读取接口做缓存和基础限流，避免 4 核 4GB 单节点被无效请求拖垮；
- 完成移动端、桌面端、备份恢复和发布回滚检查。

完成条件：Web 版本可以作为稳定内测版本持续运行，再进入公开测试和变现评估。

## 本阶段明确不做

- 不把小程序页面照搬成 Web，也不反过来用 Web 的导航和信息密度限制小程序；
- 不实现 AI 自动发布、无边界全网抓取或通用聊天机器人；
- 不在没有留存数据前增加广告、积分商城和复杂会员体系；
- 不因小程序备案审核等待而暂停 Web Phase 2。

## Phase 2 验收标准

- 未注册访客打开首页即可阅读，不需要先选分类或搜索；
- 首页连续浏览时能看到多个领域，刷新不会只重复固定前两项；
- 每篇正式常识能在较短篇幅内直接回答标题，并提供至少一个自然延伸方向；
- 相关常识、收藏和反馈在刷新后状态正确，权限边界不被客户端绕过；
- 来源变化或覆盖缺口能形成内部候选，进入 AI 处理和人工审核队列；
- Web 移动端和桌面端通过真实浏览验收，错误和空状态可理解；
- 关键指标可查看：有效阅读、继续阅读、收藏、有用率、领域覆盖和待审核积压。

## 里程碑与决策门

| 里程碑 | 交付物 | 决策门 |
| --- | --- | --- |
| M1 内容基线 | 20 篇 starter 完成复核，开始批量补齐 V1 | 内容不闭环不扩大流量 |
| M2 浏览闭环 | 未读优先、连续阅读、搜索兜底、关系路径 | 桌面和移动端各完成一次真实验收 |
| M3 反馈闭环 | 正式内容反馈、收藏和基础统计 | 先看留存和有效阅读，不急着做个性化 |
| M4 供给闭环 | 来源变化到候选审核全链路可观测 | AI 仍不能自动发布 |
| M5 Web 内测版 | 性能、限流、备份、回滚和上线清单 | 再决定小程序适配和公开测试 |

## 小程序后续策略

小程序暂时只维护可编译的技术切片和 API 对接，不继续追求与 Web 功能同步。待 Web Phase 2 的内容结构、推荐信号和关系路径稳定后，另立小程序适配阶段，重点重新设计：

- 单手操作和弱网加载；
- 更低的信息密度和更短的阅读卡片；
- 微信登录、分享和收藏习惯；
- 真机尺寸、合法域名、备案和提审要求。
