# 候选内容统一约定

- 所有新公开候选（Web、小程序、投稿 API、内部编辑、抓取生成）都必须有 proposedTitle（2～80 字）和 statement（12～160 字）。statement 即摘要/核心结论，不增加重复摘要字段。
- whyUseful 用于解释与用途；applicability 表达必要边界；sourceUrl 提供依据。共享 schema 与数据库创建入口均校验标题和摘要。
- 私密随手记不是公开候选：content 仍允许 1～5000 字，不强制标题。个人记录 API 不能发布。转投稿只带入原文和来源，用户补齐标题、摘要后才提交同一个投稿接口；超长原文完整保留供提炼，不截断冒充摘要。
- 新增草稿入口必须沿用上述两阶段约定，不得通过直接写数据库绕过候选校验。
- 历史无标题候选展示“话题 · 候选试读”，不自动改写原始数据。初审通过前需要审核人确认标题；已进入试读的历史项仍可浏览，正式发布时确认标题。
- Web /submissions/:id 与小程序 pages/submission/index 提供候选详情；始终标记未正式收录，不混同正式知识节点。
- 部署后旧客户端不带标题的投稿将收到校验错误。需同步发布新版小程序；不通过自动截取正文掩盖旧客户端缺字段。
