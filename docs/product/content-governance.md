# 内容供给、投票与审核规则

## 设计原则

内容治理要同时守住四条边界：开放贡献不等于公开直发；用户认为有用不等于事实为真；AI 改写不等于人工审核；热点信息不等于长期常识。

## 三条独立流水线

### 实时信息

```text
discovered → fetched → normalized → screened
           → visible_realtime / held / expired
```

实时信息来自白名单 RSS、API、允许抓取的网页或人工录入。它只展示“来源说了什么”，必须带来源与时间，不能直接代表平台结论。过期后可以删除快照、只保留元数据，或转入候选加工。

### 候选精华

```text
submitted → automated_screening → trial
          → expanded_trial → queued_for_review
          → merged / rejected / withdrawn
```

进入 `trial` 前必须完成结构、重复、来源可访问性、敏感信息、侵权风险和内容安全检查。AI 可生成更精炼的展示稿，但原始投稿不变。

### 内部编辑候选

```text
coverage_gap / source_discovery / maintenance
          → automated_screening → queued_for_review
          → draft / merged / rejected / held
```

内部编辑候选用于保证没有用户投稿时百科仍能增长和更新。它必须记录触发原因、原始来源、AI 处理、覆盖影响和风险，但不需要凑够公开票数。它不进入用户投稿排行榜，不伪装成用户内容，也不能绕过人工审核发布。

用户候选和内部编辑候选可以共用版本、来源、AI 作业、审批和审计能力，但必须通过 `origin_type` 区分来源。公开投票门槛只约束 `user_submission`；覆盖优先级、来源更新和复核到期驱动内部候选的审核顺序。

### 正式常识

```text
draft → pending_review → approved → published
      → superseded / archived
```

候选晋级只会创建 `draft`。从 `approved` 到 `published` 需要明确的人类审核动作；修改已发布内容必须创建新版本，旧版本可回看和回滚。

## 首版阈值

| 阶段 | 默认条件 | 结果 |
|---|---|---|
| 小流量尝试 | 自动检查全部通过 | 进入限定流量候选池 |
| 扩大尝试 | 有用数 ≥ 5、净有用数 ≥ 4、有用率 ≥ 70% | 扩大候选曝光 |
| 正式审核 | 有效评分 ≥ 20、有用率 ≥ 80% | 加入人工审核队列 |

其中：

```text
有用率 = 有用票 /（有用票 + 没用票）
净有用数 = 有用票 - 没用票
```

首版采用易解释的固定阈值，所有数值通过配置保存，不写死在客户端。样本增加后可以引入带先验的置信区间，但不能只用百分比处理小样本。

以下情况会阻断自动晋级：来源不足或失效、与权威来源冲突、疑似抄袭、涉及高风险主题、存在隐私或安全问题、异常投票比例过高。

## 有效评分与反作弊

- 登录用户对同一候选只有一个当前评分，可以修改，不能重复累加；
- 作者对自己内容的评分不参与门槛；
- 记录评分时间、账号、候选版本和必要的风控信号；
- 批量注册、设备或网络异常、互刷团伙和极短时集中评分可降权或剔除；
- 评分统计需要可重算，算法和阈值变更保留版本；
- 管理员不能直接篡改票数，只能标记无效评分并记录理由；
- 候选正文发生实质变化时，进入新候选版本并重新计算可比评分。

## 审核结果

审核者可以：

- 通过并创建新的正式常识；
- 合并到已有正式常识的新版本；
- 退回补充来源或适用边界；
- 驳回垃圾、侵权、虚假或不适合沉淀的内容；
- 暂缓高风险或无法及时核验的内容。

审核界面必须同时展示原始投稿、AI 改写、差异、来源证据、相似内容、有效评分、风险提示和历史决策。

## 内容更新

正式常识按稳定性设置复核周期：

- 稳定事实：每 12—24 个月检查；
- 制度、政策和统计指标：每 1—6 个月检查；
- 热点关联内容：每 1—7 天检查，稳定后降低频率；
- 来源失效：每周批量扫描。

发现新信息时，AI 只能提出“无变化、补充、冲突、过期、下架建议”之一，并附来源与差异。高风险主题、删除、合并和正式发布继续由人工确认。

## 举报与申诉

公开页面不提供讨论区，但必须提供私有举报 / 纠错入口。举报理由包括违法不良信息、事实错误、过期、来源不支持、侵权、隐私泄露和其他。系统记录受理、处理、反馈与复核状态；内容作者可以看到与自己相关的结果并申诉。
