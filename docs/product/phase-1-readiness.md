## 已确认的产品决策

- [x] 产品定位为打开即看的主动推荐型常识百科，不是搜索型知识库或问答社区；
- [x] 分开建模兴趣、话题、实时信息、热点、候选精华和正式常识；
- [x] 允许用户提交直接陈述结论的候选精华，不允许无审核直发正式内容；
- [x] 公开互动只有“有用 / 没用”，举报和纠错为私有流程，不开放评论；
- [x] 投票负责筛选加工价值，来源和审核负责事实可信度；
- [x] 首版门槛为有用数 ≥ 5、净有用数 ≥ 4、有用率 ≥ 70% 时扩大尝试；20 个有效评分且有用率 ≥ 80% 时进入审核，后台可配置；
- [x] 前台昵称化，公开身份与后台合规认证分离；
- [x] AI 负责检查、提炼、更新和建议，人工负责正式发布与高风险动作；
- [x] 网站与小程序共用 API，网站先承担完整投稿和审核；
- [x] 服务器采用低成本单节点起步，以静态化、缓存和异步任务提高效率；
- [x] 版权、隐私、AI 标识和内容安全的最低要求在上线前完成，商标、软著和系统化维权按运营信号投入。

## Phase 1 的唯一范围

Phase 1 只实现“内容内核与审核闭环”：

1. 数据库迁移：领域、兴趣、话题、实时信息、热点、来源、候选、评分、正式节点、版本、claim、关系、AI 作业、审批和审计；
   候选必须区分用户投稿与覆盖缺口、来源发现、维护、站长种子等内部来源；
2. 服务端状态机、投票有效性、晋级判定和权限规则；
3. 来源、候选投稿、AI 预处理占位 Adapter、审核和发布 API；
4. 网站端最小投稿页和管理审核页；
5. 录入 20 个结构化 starter 节点和 10—20 条候选样例；
6. 验证原稿—AI 稿—人工稿—发布版全链路可追溯；
7. 为关键领域规则、迁移和 API 建立自动测试。

Phase 1 不实现公开搜索、完整学习系统、小程序业务页面、真实抓取和公开 AI 问答，避免同时打开过多战线。

## Phase 1 完成标准

- 任一正式内容都能追溯来源、候选、AI 处理、审核者和版本；
- 票数聚合可从原始评分重算，异常或作者评分不影响晋级；
- 候选不能通过客户端或 AI 绕过审核进入发布态；
- 没有用户和投票时，内部编辑候选仍能由来源或覆盖任务进入站长审核；
- 已发布版本不可覆盖，可发布新版本并回滚；
- 正式短文必须直接回答标题，至少两个短段落、必要边界和可核验来源；
- 权限、审计、阈值和来源规则有测试；
- 20 个 starter 节点证明内容模型、完整短文展示和阅读时长字段可用；正式公开前仍需逐条编辑核验来源；
- `pnpm check` 全部通过，并有一次数据库迁移回滚或恢复验证记录。

## Phase 1 后的顺序

```text
Phase 2 浏览优先的百科网站 + 最小内部供给循环
   → Phase 3 来源监测、覆盖缺口与 AI 批量审核工作台
   → Phase 4 浏览优先的微信小程序
   → Phase 5 个性化、收藏同步与可选学习系统
   → Phase 6 备案、压测、公开测试与变现验证
   → Phase 7 带来源 AI 问答（可选）
```

投稿功能可以在 Phase 1 做内部闭环，但只在身份、协议、内容治理和备案门全部满足后对公众开放。
