# 常识地图 MVP 产品基线

- 版本：1.2
- 日期：2026-09-03
- 状态：产品方向已校准，Phase 1 工程已封板

## 一句话定位

常识地图是一套可以随手翻的主动推荐型常识百科：用户不必先有问题或搜索词，打开后就能看到简短、可信、有趣、能继续延伸的常识；感兴趣时再沿话题、关系或外部来源深入。

它不是以搜索为中心的资料库，也不是开放直发社区、新闻采编系统、可自由改写的百科或让 AI 无审核发布答案的聊天机器人。搜索是辅助入口，个人知识库和学习系统是后续增强能力。

## 首批用户与核心价值

首批用户是 20—45 岁、希望补充通识和理解现实背景，但通常不知道“自己不知道什么”的成年人。产品优先解决四个问题：

1. 不要求用户先搜索，打开即可获得一个有价值的认知增量；
2. 从兴趣和现实热点进入，但最终沉淀为可长期复用的常识；
3. 用“有用 / 没用”反馈识别值得继续加工的内容；
4. 用来源、版本、审核和持续复核，避免把热度误当成事实。

北极星指标改为“每周有收获浏览会话数”：一次会话完成至少 3 条有效阅读，并出现收藏、有用或继续了解中的至少一个行为。供给侧同时跟踪领域覆盖率、候选采用率、单条审核时间、来源失效和过期内容处理时长。

完整定位、浏览闭环、自迭代和变现边界以 [产品愿景与闭环](./product-vision-and-loops.md) 为准。

## 浏览优先的核心体验

```text
打开即看到常识 → 换一条或继续了解 → 发现兴趣 → 沿关系深入 → 下次推荐更合适
```

- 首页首屏不是搜索框或登录提示，而是一条 30—90 秒可读完的常识卡；
- 默认提供“随便看看”“今天值得知道”“你可能感兴趣”和“沿着这个继续”；
- 每张卡包含一句话结论、为什么值得知道、例子或误解、必要边界、来源和复核时间；
- 公开反馈保持“有用 / 没用”，不增加评论；换一条、继续阅读和收藏用于优化个人体验；
- 推荐保留跨领域探索，不能只按点击率和热点制造信息茧房。

## 无用户时的自迭代闭环

```text
常识覆盖地图 → 缺口或过期扫描 → 白名单来源 → AI 候选/更新建议
      ↑                                      ↓
      └──── 发布后复核 ← 站长批量审核 ←──────┘
```

系统必须能在没有投稿和反馈时继续增长。AI 根据覆盖缺口、来源变化、关系断点和复核日期创建候选及审核摘要，站长只做批准、修改、合并或驳回。正式发布仍不能绕过人工审核。

## 内容分层

产品中的概念必须分开，不能全部叫“知识点”或“热点”：

| 层级 | 含义 | 是否长期保存 | 是否代表平台结论 |
|---|---|---:|---:|
| 兴趣 `interest` | 用户想持续关注的方向 | 是 | 否 |
| 话题 `topic` | 组织内容的稳定主题 | 是 | 否 |
| 实时信息 `realtime_info` | 新抓取或新提交、尚待核实的信息线索 | 短期 | 否 |
| 热点事件 `hot_event` | 一段时间内关注度快速上升的现实事件 | 按价值决定 | 否 |
| 候选精华 `submission` | 用户或系统提交的简短结论 | 是 | 否 |
| 正式常识 `knowledge_node` | 经来源核验、AI 整理和人工审核的正式内容 | 是 | 是 |

兴趣决定个性化入口，话题负责归类，热点负责解释当下，候选精华负责开放供给，正式常识才进入长期知识体系。

## 核心内容循环

```text
用户投稿 → 自动检查 → 尝试展示 → 有用 / 没用 → 达标后审核 ┐
                                                              ├→ 人工审核 → 发布/合并
覆盖缺口 / 来源变化 → AI 编辑候选 → 来源与风险检查 → 直接审核 ┘
       ↑                                                         ↓
       └──────────── 来源、冲突、时效和覆盖率定时复核 ───────────┘
```

投票只用于判断用户投稿“是否值得继续加工和展示”，不用于证明真假。系统编辑候选由覆盖优先级、来源变化或维护任务驱动，不因没有用户投票而停滞。两条通道的事实是否成立都由来源证据和人工审核决定。

所有候选必须记录 `origin_type`：`user_submission`、`source_discovery`、`coverage_gap`、`maintenance` 或 `admin_seed`。只有 `user_submission` 默认进入公开尝试池；其他类型进入内部审核队列，不伪装成用户投稿，也不占用公开票数。

## 投稿形态

任何满足账号要求的用户都可以提交候选精华，但不能无审核地直接写入正式常识。投稿不是提问，必须直接陈述结论，并填写：

- 一句话结论；
- 为什么有用；
- 适用条件或例外；
- 至少一个可核验来源，纯经验内容需明确标为个人经验；
- 话题和时效性；
- 是否包含 AI 生成或改写内容的声明。

前台只保留“有用”“没用”“举报 / 纠错”三个反馈动作，不提供公开评论、回复、私信和自由编辑入口。举报与纠错进入私有审核队列，不形成讨论区。

## 首版尝试展示与晋级门槛

门槛必须后台可配置并保留变更记录。冷启动默认值为：

1. 自动检查通过后，候选内容可进入小流量尝试池；
2. 累计至少 5 个“有用”、净有用数至少 4、有用率至少 70%，扩大尝试展示；
3. 累计至少 20 个有效评分且有用率至少 80%，进入正式常识审核队列；
4. 高风险主题、来源不足、相互冲突或疑似侵权内容，无论票数多少都不能自动晋级；
5. 票数达到门槛不等于审核通过，审核者可以合并、退回、驳回或要求补充来源。

有效评分以一账号一票为基础；作者自己的票不计入，异常账号、批量注册、互刷和短时间集中投票应降权或剔除。首版不向用户展示复杂置信分，只展示有用数、没用数和当前状态。

## 账号原则

- 访客无需登录即可阅读正式常识；
- 浏览、换一条、选择临时兴趣和设备内保存已读记录不需要账号；
- 前台只展示随机昵称或用户自选昵称，不展示真实姓名、手机号等身份信息；
- 云端收藏、跨端同步和有效投票需要轻量登录，但不要求公开实名；
- 公开身份与后台合规身份分离，后台只收集提供对应功能所必需的信息；
- 不提供完全无账号投稿，以便防刷、撤回、申诉和审计；
- 对外提供信息发布功能前，按现行规则确认并实现所需的后台真实身份认证；投稿者可选择公开昵称或不公开署名。

账号和权限细则见 [身份与权限](./identity-and-permissions.md)。

## MVP 必须具备

- 无需登录浏览正式常识；
- 打开即看的常识流、换一条、关系延伸、跨领域探索和已读去重；
- 领域、兴趣、话题、实时信息、热点、候选精华和正式常识的独立模型；
- 用户候选与系统编辑候选的来源类型、独立晋级路径和统一人工发布门；
- 节点、不可变版本、来源、claim 和关系；
- 网站端结构化候选投稿、AI 预处理、尝试展示、投票和人工审核；
- 网站端管理后台的草稿、合并、审核、发布、撤回和回滚；
- 小程序端常识流、关系延伸、辅助搜索、有用 / 没用和收藏；学习与复习作为后续增强能力；
- 最小覆盖缺口扫描和白名单数据源增量检查，所有外部内容先进入待处理区；
- AI 批量生成候选、更新建议和审核摘要，站长只处理审批队列；
- 来源、AI 处理、审核、阈值变化和正式发布的审计记录；
- 私有举报 / 纠错入口与处理状态；
- Markdown/JSON 个人数据导出。

## MVP 明确不做

- 无审核直发、公开评论、回复、私信或自由编辑正式常识；
- 把票数、热度或 AI 置信度当作事实证明；
- AI 自动发布、删除或大幅改写正式内容；
- 小程序复杂投稿编辑器，首版投稿以网站为主；
- 无边界全网抓取或复制未授权教材、书籍、付费文章、新闻全文；
- 通用聊天机器人、独立新闻采编、全学科一次覆盖；
- 微服务、Kafka、Neo4j 或独立搜索集群；
- 在验证留存前投入广告系统、积分商城和复杂会员体系。
- 把搜索框、AI 聊天、登录或投稿作为首页唯一主入口。

## 首发内容与阶段顺序

首批编辑生产采用广度优先：先覆盖 12 个一级领域，每个领域给出少量能闭环阅读的代表性常识，再逐步加深到 48 个细分话题。首页混合推荐，不要求用户先选择学习路径。

Phase 1 先用 20—30 个真实正式节点和 10—20 条候选精华验证模型、审核和晋级流程。公开测试目标再扩展到 150—250 个正式节点和 300—500 道题，不用批量抓取代替内容设计。

## 产品红线

- AI 永远不能绕过人工审核进入正式发布态；
- 原始投稿、AI 改写稿和最终稿必须分别保存并可比较；
- 抓取内容必须记录来源、许可、访问时间和内容指纹；
- 医疗、法律、金融、未成年人、公共事件等高风险内容使用更严格模板和审核策略；
- 所有对外的 AI 生成合成内容按适用规则标识；
- 任何增长目标都不能覆盖来源、版权、隐私和内容安全门槛。

## Phase 1 的准入条件

Phase 1 只在 [Phase 1 准入清单](./phase-1-readiness.md) 获产品负责人确认后开始。服务器、域名和备案不是本地 Phase 1 的前置条件，但在公开部署和小程序提审前必须完成。
