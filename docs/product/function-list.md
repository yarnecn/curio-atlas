# 功能清单与使用方法

这是一份操作说明。当前页面和 API 已可本地运行。

## 访客

| 功能 | 入口 | 是否注册 | 怎么用 |
| --- | --- | --- | --- |
| 随便看常识 | `/` | 不需要 | 打开首页阅读最多 12 条短文；内容按一级领域库存比例混排，可筛选或“换一批”。 |
| 按创建者筛选 | 首页来源筛选或资料卡片的小标记 | 不需要 | 可只看系统内容、站长创建或用户投稿；用户投稿会显示公开昵称。 |
| 连续看相关常识 | 首页标题或“读完整内容” | 不需要 | 进入详情后从“顺着看”继续点击相关内容。 |
| 阅读候选 | `/submissions` | 不需要 | 查看进入小流量尝试池的用户投稿。 |
| 评价有用性 | `/submissions` | 昵称账号 | 点击“有用”或“没用”；同一用户可修改当前评价，不会重复累加。 |
| 提交候选精华 | `/contribute` | 昵称账号 | 选择话题，直接写结论、用途、边界和来源，再提交。 |

首页只展示正式常识。候选的“有用”只代表值得继续加工，不代表事实已经被确认。

## 站长 / 审核者

| 功能 | 入口 | 怎么用 |
| --- | --- | --- |
| 查看审核队列 | `/admin/review` | 对照原稿、AI 稿、来源、票数和边界；话题已在入库时分好，审核者不需要重新选择。 |
| 管理分类与 AI | `/admin/operations` | 新增或停用领域、话题，选择零 Token、本地或远程兼容模型。 |
| 管理白名单来源 | `/admin/operations` | 添加单页或站点入口，手动立即抓取或定时维护，并查看证据包和错误。 |
| 批量导入来源 | `/admin/operations` → 批量导入来源 | 每行一个 HTTPS 页面或站点入口，单次最多 200 个；格式见页面提示。 |
| 查看 V1 内容进度 | `/admin/review` 顶部 | 查看各话题已发布、待审核和目标数；用下方筛选器逐话题验收。 |
| 创建内部候选 | `/admin/review` → 创建内部编辑候选 | 用于覆盖缺口、来源发现和维护，不需要公开凑票。 |
| 创建正式常识 | 审核卡片 → 创建正式常识 | 填标题、slug 和理由，发布后进入首页。 |
| 合并到已有常识 | 审核卡片 → 选择同话题已有常识 → 合并 | 只在内容重复时使用；追加新版本，旧版本保留。 |
| 暂缓 / 驳回 | 审核卡片 | 暂缓保留待查，驳回结束当前候选。 |
| 查看版本 | `/admin/knowledge` | 选择正式常识，查看版本和发布时间。 |
| 回滚版本 | `/admin/knowledge` | 填写至少 4 个字的理由，点击目标旧版本的回滚。系统生成新的当前版本。 |

## 首次创建站长登录

复制 `config/app.config.example.json` 为 `config/app.config.json`，修改 MySQL、Redis、`owner.handle` 和 `owner.initialPassword`，执行 `npm start`。首次启动会创建站长，日常启动不会修改已有密码。然后访问 `/login` 登录；公开注册只会得到普通用户权限，不能进入后台。

## 一次批量抓取

在 `/admin/operations` 新增单页或站点来源，然后点击“立即抓取”；需要持续维护时勾选自动维护，并在配置文件启用全局自动任务。完整操作见 [页面与网站抓取](../operations/bulk-source-run.md)。

## 常见提示

- “来源不足”：非个人经验投稿必须填写可访问来源。
- “内部候选不参与公开评分”：这是预期行为，内部任务直接进审核队列。
- “审核队列为空”：没有待人工处理内容，不是系统故障。
- “当前版本”：当前版本不能回滚到自己；选择其他历史版本即可。
- 首页没有内容：先检查启动日志中的 MySQL 初始化结果和 `/api/health`，再查看浏览器网络错误。
- 审核台数量与首页不同：审核台包含未发布候选和版本记录；首页只从已发布常识中每次推荐最多 12 条。运行 `npm run content:status` 可核对准确数量。
