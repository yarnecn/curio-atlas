# 常识地图内容录入与体验改进

## 工作环境与默认行为

- 网站：https://atlas.yarne.cc/；源码：`C:/workspace/idea-t`。用户指定其他环境时以用户指定为准；操作前明确线上内容和本地代码属于不同环境。
- 用户要求“录入”且未指定去向时，默认整理并提交待审核候选；要求“记一下”时保存私密随手记；要求只整理时不提交。说明采用的默认值即可，不为已授权录入反复确认。
- 同时处理录入路径中实际发现、可复现的体验缺陷，完成相关代码修复与验证。用户要求仅录入或仅记录问题时遵从该限制。不要借此全面重设计产品。
- 修改本地代码不等于线上修复。部署、正式收录、合并或覆盖已有内容按用户明确授权执行；已有授权不重复询问。默认投稿不包含这些动作。

## 先核对产品现状

读取源码根目录适用的 `AGENTS.md`（若存在）、`docs/START-HERE.md`、`docs/operations/submission-initial-review.md` 和 `docs/product/source-review-policy.md`。内容字段与代码入口见 [产品参考](references/product.md)。只读对应任务需要的文件。

本地未提交改动可能尚未上线。字段、可用话题和线上操作以当前页面及响应为证据；校验规则参考当前源码，不凭旧选择器或此技能的字段快照强行提交。

## 整理输入

1. 保留原意，将素材拆为可以独立理解的知识点，避免一条塞入多个不相关结论。不要为了凑数量拆碎同一论点。
2. 提炼具体标题、简短结论、用途、必要的条件或例外，以及用户提供的来源。区分事实、推断与个人经验；不把用户未说明的内容标为亲身经历。
3. 通过 ego-browser 阅读用户给出的链接和需要核实的资料。对时效性强、专业或高风险事实查证原始权威来源。来源可选，缺少网址不是自动阻止投稿的理由，但不得编造来源或把未验证说法写成已证实结论。关键疑点无法消除时说明并保留草稿，不用肯定语气提交。
4. 在首页用标题及关键概念查重；有权限时也检查已有候选。记录搜索范围，不把“公开搜索未找到”称为全库无重复。明确重复的内容跳过；补充或纠错形成更新建议，不默认修改正式内容。
5. 使用真实话题列表匹配领域，禁止猜测 UUID。没有合适话题时保留待处理条目并说明，不静默创建分类或归入明显无关类别。
6. 由本助手生成或改写的候选如实勾选 AI 声明。可选边界没有必要内容时留空，不用“无例外”之类填充。

## 通过产品录入并验证

读取当前环境提供的 ego-browser 技能并运行 `ego-browser skill`，遵循当前 CLI 指南；优先走真实页面以发现体验问题，不绕过表单直接写数据库。一个录入任务使用一个 TaskSpace。

- 默认入口 `/contribute`；私密随手记入口 `/notes`。投稿会登记 AI 预处理任务，不能把它称为已初审、已公开或已正式收录。
- 利用已登录会话；需要登录时交还浏览器让用户登录，不从配置、浏览器存储或日志提取密码和会话。继续使用原任务空间。
- 用户授权录入后可直接填写和提交，无需逐条再次确认。输入有实质歧义时只询问影响录入的部分，继续处理其余明确内容。
- 批量时先完成一条并验证实际回执，再继续其余条目。每条保存标题、返回编号、实际状态和可访问链接；链接必须由页面或响应证实，不编造未公开候选的公开链接。
- 提交超时或结果不明时，先核对页面、回执和可访问列表，不盲目重复提交。无法确认某条是否保存时标记“待确认”，不要再提交该条；其他独立条目可以继续。
- 随手记转投稿保留原记录，不删除原稿。只有用户指定 API 录入或批量效率优先且不需要 UI 验收时，才使用已确认的产品 API；私密记录令牌不能用于投稿或审核，重试规则见产品参考。
- 完成后依照浏览器技能结束任务空间；需要用户接管登录时保持空间供继续使用。

## 使用中修复代码

先记录最短复现步骤、所在环境、预期/实际表现及必要截图，再定位代码。检查 `git status --short` 与相关 diff，保留用户已有改动；不重置或覆盖其他工作。

可直接修复与此次使用相关的表单提示、输入丢失、加载/空状态、响应式布局、键盘操作、重复提交防护等可验证缺陷。避免将个人审美偏好当成 bug。产品规则、身份权限、审核门槛、数据模型或大规模重构有独立影响，不从“顺手优化”推导授权；先完成可独立交付的修复，再提出具体方案。

- 修改 Web 前读 `apps/web/AGENTS.md` 要求的本地 Next.js 指南。
- 遵循仓库要求的检查；代码修复前按 `docs/START-HERE.md` 建立 `pnpm check` 基线。若失败，区分原有问题与本次问题，不顺带清理无关失败。
- 页面修改至少运行 Web 的 lint、typecheck、build；业务逻辑补充有意义的回归测试。若涉及共享契约，验证受影响调用端；数据库变更按仓库文档完成 schema、初始化与烟测要求。
- 在本地可用服务复现原路径，布局问题检查桌面与手机宽度。启动 `pnpm start` 会初始化数据库；先确认目标为本地开发服务，不用生产配置启动调试或写测试数据。
- 本地依赖或服务不可用时如实说明未完成的验证，不把静态检查称为浏览器验证，也不向生产录入测试垃圾数据。
- 未部署时明确“本地已修复，线上仍是旧版本”。线上阻碍不能靠未部署补丁假装解决；保留已整理内容和已完成回执，只对剩余需要的操作请求用户决定。

## 审核边界与交付

当前产品链路为：提交 → 自动预处理 → 人工初审 → 公开试读 → 人工正式收录。票数与来源有无都不能代替人工决定。默认止于提交待审核；用户明确审核并授权具体条目时，可以代为执行界面动作并保留真实审核理由，不冒充独立人工核验，不绕过状态机。

结束时简洁报告：

- 内容：已提交/已保存、跳过重复、待处理或待确认的条目及原因；附编号和可用链接。
- 修复：实际问题、修改文件、已完成检查和未完成验证。
- 上线：明确代码是否已部署；没有改代码或没有部署时直说。

不要将私密原文或令牌放进仓库中的体验报告。跨回合需要保存草稿时使用用户指定的私密位置；公开候选与私密记录保持区分。
