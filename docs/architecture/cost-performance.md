# 低成本部署与性能方案

## 目标

先保证打开即看的常识体验可用、稳定、便宜，再按真实流量扩容。首版不为假设中的大流量支付微服务、集群和多套托管组件成本，而是通过静态化、推荐预计算、缓存、异步化和监控提高单机效率。

## 首次购买建议

服务器品牌和活动价格变化快，采购时再比价。能力基线建议：

- 中国大陆地域，和备案主体、目标用户区域及云服务商备案流程匹配；
- 2 vCPU / 4 GB 内存作为更稳妥的公开测试起点；
- 2 GB 内存只适合极小内测，需要 swap、低并发 worker 和严格内存限制；
- 系统盘使用 SSD，容量从 40—80 GB 起，根据备份与图片策略调整；
- 使用长期支持版 Linux、SSH 密钥、云防火墙、快照和基础监控；
- 优先选择可随时升配的实例，不为多年高规格资源预付；
- 图片和下载文件使用同地域对象存储，避免在主机上运行生产 MinIO；
- 静态资源通过 CDN，动态 API 保持同地域短链路。

域名建议至少划分 `www`、`api` 和 `static`，但首版可以让 `www` 与 `api` 指向同一主机，由反向代理分流。

## 首版生产拓扑

```text
用户 / 微信小程序
        ↓ HTTPS
CDN（静态资源与可缓存公开页）
        ↓
反向代理
  ├── Next.js Web
  ├── NestJS API
  └── 健康检查与限流
        ↓
MySQL + Redis + 单并发 Worker
        ↓
对象存储 / 白名单来源 / AI API
```

同一台主机可先运行反向代理、Web、API、MySQL、Redis 和 worker。生产数据库数据、对象文件和日志必须有主机外备份。开发用 MinIO 不进入这套生产基线。

## 有限资源下的优化顺序

1. 正式常识公开页优先静态生成或增量再生成，避免每次请求查询数据库；
2. 匿名常识流按领域、时效和质量批量预计算并缓存，不为每次换一条实时调用 AI；
3. CDN 缓存静态文件、分享图和允许缓存的公开响应；
4. API 使用分页、字段裁剪、条件请求、压缩和合理 Cache-Control；
5. MySQL 先做好索引、慢查询和连接数控制，不先引入独立搜索；
6. Redis 设置最大内存和淘汰策略，只存可丢失数据；
7. 抓取、AI、导出、索引、推荐候选集和简报全部异步，worker 首版并发为 1；
8. 相同 AI 输入和版本结果缓存，定时任务合并批处理；
9. 图片上传时生成有限规格，禁止请求时反复做高内存转换；
10. 日志结构化并轮转，不在系统盘无限增长；
11. 用 P95 延迟、错误率、CPU、内存、数据库和队列数据决定优化，不凭感觉拆服务。

## 资源保护

- 反向代理限制请求体、连接数和明显恶意频率；
- 访客、登录用户、投稿、搜索和 AI 分别设置限流；
- 数据库连接池设置硬上限，避免进程数乘连接数耗尽内存；
- Redis 建议从 128 MB 最大内存起，根据命中率调整；
- worker 支持暂停、超时、幂等、重试上限和失败队列；
- 高峰时优先保障正式内容阅读，暂停抓取、批量 AI 和大导出；
- 页面在外部 AI、来源或对象存储故障时仍能读取已发布内容。

## 性能目标

公开测试的首个服务目标：

| 指标 | 目标 |
|---|---:|
| 月可用性 | ≥ 99.5% |
| 缓存命中公开页 P95 | ≤ 500 ms |
| 普通 API P95 | ≤ 800 ms |
| 5xx 错误率 | < 1% |
| 数据库主机外备份 | 每日 |
| 恢复演练 | 每季度 |

这些是公开测试目标，不是昂贵的强 SLA。前端还需跟踪真实用户的页面加载指标，并优先压缩 JavaScript、字体和图片。

## 扩容触发器

先优化再扩容，但连续 7 天满足任一条件就进入容量评审：

- 高峰 CPU 持续超过 70%；
- 可用内存持续低于 20% 或频繁使用 swap；
- 普通 API P95 连续超目标且不是单个慢查询；
- 数据库 I/O 或连接池持续饱和；
- 关键队列最长等待超过 15 分钟；
- 单机故障造成的业务损失已高于冗余成本。

演进顺序一般是：静态资源和图片外置 → 主机升配 → 数据库独立或托管 → worker 独立 → 增加缓存与只读副本 → 最后才评估服务拆分。每一步必须有监控证据和回滚方案。

## 采购与上线交接

用户负责购买服务器、域名和办理备案；工程侧在采购前提供规格核对，在采购后完成：

- DNS、HTTPS、反向代理与安全组配置；
- 单一只读配置文件与密钥挂载；
- 数据库初始化、备份、恢复验证和最小权限；
- Web/API/worker 进程守护与开机恢复；
- 监控、告警、日志轮转和成本仪表盘；
- 网站备案号展示、小程序合法域名与提审配置；
- 灰度、冒烟测试和回滚演练。

购买前不要提前锁定长期高配套餐；等 Phase 2 的公开页面和压测数据出来，再给出具体云厂商、地域、带宽和实例建议。
