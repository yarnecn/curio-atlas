# AI 管理员与模型成本方案

## 角色定位

AI 管理员负责让网站持续运转得更省力，不代替产品负责人承担发布和治理责任。它可以观察、整理、检测、提出变更并执行已授权的低风险任务；所有重要内容和生产变更仍由人审核。

```text
观察 Observe → 建议 Propose → 自动验证 Validate
       → 等待审批 Approve → 执行 Execute → 可回滚 Rollback
```

## 可自动执行的低风险任务

- 扫描跨领域常识覆盖地图，发现空白、薄弱节点和关系断点；
- 检查来源更新、死链、重复内容和复核到期；
- 给实时信息分类、打标签、聚类和提取候选事实；
- 对投稿做结构检查、敏感信息提示、相似度和来源可用性检查；
- 生成简短改写稿、摘要、标题备选和变更差异；
- 运行内容校验、固定评测、性能巡检和成本报告；
- 创建待办、草稿或审批请求；
- 在明确预算和速率限制内重试幂等任务。

这些任务不能依赖用户搜索、投稿或反馈才触发。没有外部用户时，覆盖缺口、来源变化、复核到期和关系完整性仍会持续生成内部任务。

## 必须人工批准的动作

- 正式常识的首次发布、合并、删除、撤回和重大改写；
- 医疗、法律、金融、未成年人、公共事件等高风险内容；
- 来源白名单、晋级阈值、风控规则和用户处罚变化；
- 向外部 AI 服务发送新的数据类别；
- 数据库破坏性迁移、生产发布、扩容和新增付费服务；
- 用户协议、隐私、版权许可和运营规则变化。

冷启动阶段由产品负责人承担最终审核。未来可以逐项下放可逆、低风险、效果已量化的动作，不能一次性授予“全站自动管理”权限。

## 模型路由

不绑定单一厂商，所有调用通过模型 Adapter。按任务采用最便宜且能达标的模型：

| 任务 | 默认策略 | 何时升级模型 |
|---|---|---|
| 分类、标签、格式校验 | 小模型、批处理 | 固定评测不达标 |
| 压缩、改写、摘要 | 小模型、短上下文 | 含糊、冲突或高风险 |
| 去重与相似召回 | 规则、哈希、低成本向量 | 规则召回不足 |
| 来源与 claim 对齐 | 规则加小模型 | 多来源冲突 |
| 高风险审核辅助 | 更强模型 | 仍只给人工建议 |
| 公开问答 | 后置功能、检索增强 | 内容库和评测稳定后 |

首版不训练自有模型，不为每次页面访问实时调用模型。AI 结果预生成、可缓存、可复用，热点任务合并批处理。

## 每次调用必须记录

- 任务类型、输入数据引用和脱敏状态；
- 模型供应商、模型标识和参数；
- Prompt 模板版本与输出 Schema 版本；
- 输入 / 输出 token、费用、耗时和重试次数；
- 原始输出、解析结果、风险标记和人工结论；
- 是否面向用户展示及采用的 AI 标识方式。

生产日志不重复保存无必要的个人信息和密钥。

## 预算与熔断

- 配置单任务 token 上限、单用户日额度、全站日 / 月预算；
- 达到 70% 发预警，达到 90% 降级非关键任务，达到 100% 停止非必要调用；
- 失败重试最多两次，使用指数退避，不对同一无效输入无限重试；
- 相同内容、模型和 Prompt 版本使用结果缓存；
- 定时任务优先在低峰批处理，并限制 worker 并发；
- 每周报告“任务量、通过率、人工采用率、单条成本和节省工时”。

预算金额在选择供应商后配置，不写死在代码。当前已实现规则、本地 Ollama 和 OpenAI 兼容三种 Adapter。规则模式零 Token；本地模式不按 Token 付费但消耗机器算力；远程供应商是否赠送试用额度可能变化，不能写成系统承诺。

模型处理结构化 JSON，Ollama 使用其结构化输出能力；远程兼容接口使用 JSON 输出模式。实现依据：[Ollama Structured Outputs](https://docs.ollama.com/capabilities/structured-outputs)、[OpenAI Structured Outputs](https://platform.openai.com/docs/guides/structured-outputs)。

## 质量门

每类 AI 任务建立至少 30 个固定样例，公开问答上线前扩大到 50—100 个问题。评测至少覆盖：事实未新增、原意保留、引用支持、边界保留、拒答、敏感内容、JSON 格式和中文简洁度。

模型或 Prompt 变化先跑固定评测，再灰度到少量任务。低于基线时自动停止扩大使用，并创建人工检查任务。

## AI 生成合成内容标识

系统保存 `ai_involvement`、模型与版本等来源信息。面向用户呈现的 AI 生成或实质性改写内容，按照适用规则提供显式标识；导出的图片、音视频或文件按要求写入相应标识和元数据。纯内部审核建议不对外展示，但仍保留审计。

## 产品与工程巡检

AI 可以每日或每周生成运营建议，例如领域覆盖缺口、内容长期重复曝光、跨领域多样性不足、页面慢、候选积压、来源失效和成本异常。建议进入审批队列，并同时给出证据、预期收益、风险、验证方法和回滚方法。首版禁止 AI 直接改生产配置或部署代码。

面向站长的默认交付物是批量审核包：按新增、补充、冲突、过期和下架建议分组，优先展示高影响和高风险项，并记录每条建议被接受、修改或驳回的结果。系统以降低站长单条审核时间为优化目标，而不是追求 AI 自动发布数量。
