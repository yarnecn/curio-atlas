# ADR-0005：从空库切换到 MySQL

- 状态：已接受
- 日期：2026-09-07
- 取代：ADR-0004

## 决策

项目在尚未进入正式生产数据阶段时直接以 MySQL 8.4 空库重新开始。运行时只使用 `mysql2` 驱动和 MySQL SQL；不转换旧 PostgreSQL 数据，不维护双数据库兼容层，也不公开迁移、回滚或单独 seed 命令。

`npm start` 在启动服务前执行幂等初始化：数据库存在性检查、完整结构创建、目录与 starter 内容补齐、站长账号存在性检查。结构定义集中在 `infra/mysql/schema.sql`，运行配置集中在 `config/app.config.json`。

数据库记录 `schema.version`。当前阶段不提供旧 PostgreSQL 转换或通用迁移命令；未来镜像与已有结构版本不兼容时必须停止启动并提供该版本的明确升级说明，不能静默带病运行。

## 原因

- 项目尚无必须保留的正式数据，直接切换比长期维护兼容层更简单；
- 使用者已有 MySQL 使用偏好和运维条件；
- 单一启动入口减少本地与容器部署时漏执行步骤的概率；
- Redis 仍只承担队列与临时状态，MySQL 保持唯一事实主库。

## 约束

- 所有结构变更必须让全新 MySQL 空库能够一次初始化成功；
- 初始化逻辑必须幂等，重复启动不能重复内容或覆盖已有站长密码；
- 正式升级前必须备份并验证恢复；当前“无迁移命令”只适用于从零阶段，不代表未来可以无策略修改已有生产结构；
- 如未来需要复杂语义检索，单独评估搜索或向量服务，不因此恢复 PostgreSQL 双栈。
